Project structure

The directories separate published pages, reusable source, and files copied through to the output.

Directory layout

project/
|-- dominion.config.json
|-- tailwind.css
|-- src/                  # Pages, mapped to output paths
|-- shared/               # Flat reusable HTML source
|-- public/               # Files copied to the output root
`-- dist/                  # Generated site; build before browsing

Only HTML files under src/ become pages. The build preserves each relative path, and copies public/ files without interpreting them.

Pages and routes

A source file's path is its output path; DOMinion does not infer clean URLs or add a client-side router.

  • src/index.html becomes dist/index.html, served at /.
  • src/help.html becomes dist/help.html, served at /help.html.
  • src/reference/index.html becomes dist/reference/index.html, served by directory-index hosts at /reference/.
Browse generated pages

Build first and serve dist/. Source-only fragment tags are not meaningful browser routes.

Shared source

The flat shared/ directory holds fragments. shared/site-nav.html is included with <dominion-site-nav></dominion-site-nav>. Pages and fragments can include other fragments; inclusion nesting is supported even though nested folders in shared/ are not.

Fragments are expanded into their callers at build time. They are not copied as standalone output documents, and their custom-element placeholders do not remain in published HTML.

Public files

public/images/diagram.png is copied to dist/images/diagram.png. Root URLs such as /images/diagram.png can be adjusted for a deployment prefix; ordinary relative URLs are resolved by the browser against the generated page's URL, not the fragment source file.
