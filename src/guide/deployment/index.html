Deployment

Build once into dist/, then publish those files to any static host that serves HTML, CSS, assets, and browser JavaScript.

Local root deployment

The checked-in config uses "basePath": "/". Build and preview from the project root:

npm run build
npm run dev

The preview URL printed by dominion dev serves generated output. For a production-like static check, serve dist/ with your chosen local HTTP server; opening unbuilt source files skips fragment and script compilation.

GitHub Pages project site

A repository site is mounted below the account host at /REPOSITORY/. Configure that exact prefix, including the leading and trailing slash, before building.

{
  "basePath": "/DOMinion/"
}

npm run build

Alternatively, set the value for one build with npm run build -- --base-path /DOMinion/. CLI options override config. The docs pages author links from site root; DOMinion prefixes local root URLs in HTML attributes, including image sources, while leaving external URLs untouched.

Keep one source tree

Use "basePath": "/" for a root-mounted site or local preview. Change the config for Pages, or pass its command-line override; do not hand-edit every link for a deployment prefix.

Publish output

Run the build in your release process and publish the resulting dist/ directory. The hosting configuration must preserve its directory structure so paths such as guide/styling/index.html remain available at /guide/styling/. No Node.js process is needed after those files are deployed.

Before release

  • Build after edits and browse the generated output.
  • Verify the configured base path matches the host mount point exactly.
  • Check nested pages, page links, and public assets at the deployed prefix.
  • Confirm your host publishes dist/, not src/ or shared/.
