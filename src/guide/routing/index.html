Routing and URLs

Static routing follows output filenames. Choose explicit paths, then decide whether links are relative to the document or anchored at the site's root.

Path mapping

For a page at src/reference/index.html, link to /reference/ on directory-index hosting. For a page at src/faq.html, link to /faq.html. There is no implicit extension removal, route fallback, or browser router.

<a href="/guide/routing/">Routing guide</a>
<a href="../faq.html">FAQ beside this output page</a>

The relative link above is resolved against the generated document location. Moving a fragment to another page does not change how a browser resolves a relative URL in its expanded markup.

URL kinds

  • Site-root URL: /images/mark.png starts at the hosted site root. DOMinion prefixes local root URLs during build.
  • Relative URL: images/mark.png is interpreted from the output document's directory by the browser.
  • External URL: https://example.test/guide remains external and is not converted into a local path.
Fragment paths are not URL bases

A relative image URL in a shared fragment is not made relative to shared/. Prefer an absolute site-root URL when an asset is shared across routes.

Deployment prefixes

For a GitHub Pages project site hosted at https://account.github.io/DOMinion/, set the base path to /DOMinion/. Write internal site-root links as if the site lived at /; the build prefixes them once.

{
  "basePath": "/DOMinion/"
}

npm run build

A command-line --base-path overrides the config for one build. The same source can therefore be previewed at root locally and emitted under a project prefix for deployment.
