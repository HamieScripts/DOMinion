Styling and themes

Tailwind v4 utilities are the default. Add project tokens in one theme file, and reserve fragment-authored CSS for selectors that need native scoping.

Edit the theme

The project-root tailwind.css file is imported during each page build. Define design tokens with Tailwind's @theme; the utilities are then available to page and fragment markup.

@theme {
  --color-moss: #416d59;
  --font-display: "Iowan Old Style", Georgia, serif;
}

Use complete class names in source. DOMinion expands fragments before the Tailwind CLI scans each page, so classes in used fragments are found. Runtime-generated class names are not.

Declare runtime states

Every style needed after data arrives must be present in static source, including states not currently visible. A template is useful when runtime code may later choose one of several states.

<div aria-live="polite">
  <template><p class="bg-sky/10 text-sky">Loading</p></template>
  <template><p class="bg-moss/10 text-moss">Ready</p></template>
  <template><p class="bg-coral/10 text-coral">Could not load</p></template>
</div>

Tailwind sees the classes even while each template is inactive. Keep data selection and the finite set of styles separate; do not construct class names from API values.

Scoped escape hatch

A fragment <style> is emitted only on pages that use that fragment. Its selectors are placed in native @scope rules rooted at the fragment instance's authored root.

<article class="card">
  <h2>Card</h2>
  <dominion-badge></dominion-badge>
</article>
<style>
.card { --accent: #bf563f; border-color: var(--accent); }
.card h2 { color: var(--accent); }
</style>

The Fragment scope includes its own root and supplied slot content, but nested fragment roots and their contents are excluded from the parent's selectors. Custom properties and other normal CSS inheritance still cross that boundary; this is selector containment, not Shadow DOM or a full CSS isolation boundary.

Utilities are in Tailwind's later utilities layer, so they win when they compete with fragment rules in the components layer. Page-authored styles remain global and unlayered.

Page-specific inline CSS

Each built page gets one minified style block in its document head. This keeps generated CSS page-specific and self-contained, but repeats bytes across navigations and gives the browser no separately cacheable shared stylesheet. Shared source avoids duplicating authoring; it does not remove repeated output. Measure your own navigation and cache behavior before making performance claims.

Browser baseline

Fragment CSS requires native @scope. As of November 2026, the documented minimum stable versions are Chrome and Edge 118, Firefox 146, and Safari 26.4, including their corresponding mobile engines. DOMinion does not ship a scoping polyfill or legacy fallback.

Check the current MDN compatibility table when setting your own support policy.
