Repeated and nested instances

The gallery includes the same card fragment twice. Each card includes a nested accent fragment, uses named and default slots, and keeps independent state and script scope.

Source fragments

shared/demo-card.html 
<article class="demo-card">
  <h3><slot name="title" #required></slot></h3>
  <div data-state-output aria-live="polite"></div>
  <button type="button" data-next-state>Cycle state</button>
  <div><slot name="body" #default #required></slot></div>
  <dominion-demo-stamp>
    <span>accent inherited across the boundary</span>
  </dominion-demo-stamp>
</article>
<style>/* scoped selectors; custom properties inherit */</style>
<script>/* update this instance through root */</script>
The authored fragment has one root because it contains both behavior and custom CSS. shared/demo-gallery.html 
<section>
  <dominion-demo-card>

    <p>Default slot content</p>
  </dominion-demo-card>
  <dominion-demo-card>
    <span slot="title">Second instance</span>
    <p>Independent root and state</p>
  </dominion-demo-card>
</section>
The gallery source includes repeated card instances, and each card includes a nested stamp. The build removes all include tags.

Runtime states

Open a card's Cycle state control. Its script selects among statically authored templates for waiting, ready, empty, and error states. The output shows each card initialized independently; the complete class names stay in HTML so Tailwind can generate their styles at build time.
