Fragments and slots

A shared fragment is reusable HTML source. Every include becomes an independent fragment instance, expanded into its caller during the build.

Include a fragment

A file named shared/notice.html is included as <dominion-notice></dominion-notice>. Use lowercase kebab-case names, no attributes, and explicit closing tags. Pages may include fragments, and fragments may include other fragments.

Instances and roots

Two includes of the same script-bearing fragment create two independent initializations and private script scopes. Each executable script gets a local root reference to that instance's one authored root. Nested fragment roots belong to their own instances.

A fragment with scripts or a custom <style> block must have exactly one authored root. A static fragment without either can emit multiple roots. DOMinion removes the include placeholder; it does not add a layout wrapper or leave a browser-managed element behind.

Keep fragments dumb

Use them to reuse stable markup such as navigation, callouts, and example framing. The caller supplies content through content slots; MVP does not bind data or handlers.

Named and default slots

Declare named insertion points in the fragment. Direct supplied elements use slot="name"; one named slot may be marked #default to receive unassigned content.

Fragment declaration 
<div class="callout">
  <p><slot name="label" #required></slot></p>
  <div><slot name="body" #default #required></slot></div>
</div>
This matches the site's actual shared/callout.html. A declaration is empty: content inside a slot declaration is not supported. Caller content 
<dominion-callout>
  <strong slot="label">Before you start</strong>
  <p>Unassigned content goes to the default body slot.</p>
  <p slot="body">Explicitly assigned body content follows in source order.</p>
</dominion-callout>
Slot assignment attributes are consumed during expansion. Nested fragment includes in supplied content are expanded too.

Explicit and default content assigned to the same slot keep their source order. Unfilled optional slots emit nothing. Meaningful unassigned content without a default slot, duplicate slot names, multiple defaults, and unknown destinations fail the build.

Required is structural

Mark a slot with #required when its caller must supply at least one element or non-whitespace text node. Comments and formatting whitespace do not count. The check is structural: an empty element, hidden element, or <template> still counts as supplied content. It does not promise visible text or runtime data.

Build-time validation

Omitting content for a required slot stops the build with a source location and include chain. Optional slots emit nothing when unfilled.
