Script timing

Fragment scripts get an instance-local root. Timing directives decide when classic code runs; they do not defer downloading inline bytes.

Default and #defer

Classic fragment scripts with no directive run after parsing, when DOMContentLoaded fires. #defer names that policy explicitly. Both preserve document source order across classic blocks.

<script>
root.querySelector("[data-message]").textContent = "Ready";
</script>

#immediate

Immediate code runs synchronously when the parser reaches the script. It can query only markup parsed so far; later siblings are not present yet. Use it only when that parse-time constraint is intentional.

<p data-before>Waiting</p>
<script #immediate>
root.querySelector("[data-before]").textContent = "Seen now";
const laterExists = Boolean(root.querySelector("[data-after]"));
</script>
<p data-after>Not parsed yet</p>

#idle

Idle work becomes eligible after parsing. DOMinion uses requestIdleCallback when available and falls back to setTimeout(callback, 0). It is not ordered relative to deferred scripts, and a long callback can still block the main thread.

Execution rules

  • Each classic block has a private function scope. Bindings do not leak to sibling scripts or window.
  • Modules retain native module scope and scheduling. They may omit a directive or use #defer; #immediate and #idle are rejected for modules.
  • External fragment scripts with src are unsupported because their source cannot receive instance-local root without changing loading semantics.
  • Use directives on executable fragment scripts only. Native defer does not defer an inline classic script; DOMinion removes its own source directives from generated output.
Scheduling is not transfer

Idle scheduling does not postpone transfer of inline script bytes. It also does not promise an ordering relationship with deferred work or make expensive work nonblocking.
